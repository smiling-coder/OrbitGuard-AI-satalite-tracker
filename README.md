# ORBITGUARD AI
**Protecting Satellites. Predicting Risks. Preserving Space.**

An interactive 3D web app for learning about space debris: orbit visualisation, collision screening, trajectory prediction, simulations and reports. Built with HTML, CSS, JavaScript (ES modules), Three.js and Chart.js, plus an optional Python/FastAPI backend (NumPy, Pandas, SQLite).

> **Educational project.** Objects are simulated unless you import your own file. Results are screening estimates, not collision probabilities, and must never be used for real satellite operations.

## Data labels
| Label | Meaning |
|---|---|
| SIMULATION | Objects or scenarios generated by the app |
| IMPORTED | Objects from your CSV/TLE file (unverified) |
| SYNTHETIC | Fragments from the collision simulator |
| PREDICTION | A calculated estimate of a future state |
| UNCERTAIN | Not enough data for a reliable result |

## Features (14 pages)
1. **Mission Control** – rotating 3D Earth (Three.js), 400 simulated objects, click to inspect, metrics from the loaded data, risk list, altitude chart
2. **Object Tracker** – search, filter, sort, compare two objects, export CSV
3. **Collision Risk Analyzer** – screening over 6/24/72 h with red/yellow/green/grey ratings, optional backend check
4. **Manoeuvre Simulator** – no burn vs prograde vs retrograde, with propellant estimate
5. **Collision Event Simulator** – hypothetical collision with synthetic fragments
6. **Orbital Density Analysis** – altitude and inclination charts
7. **AI Trajectory Predictor** – physics vs quadratic fit vs linear baseline (simulation mode)
8. **Debris Detection Lab** – simulated sensor with noise and missed observations
9. **Alert Intelligence** – ranked events, status, notes (saved in your browser), CSV export
10. **Atmospheric Drag Simulator** – orbit decay under different density assumptions
11. **Orbital Data Centre** – CSV and TLE import with validation, sample download, export
12. **Space Sustainability** – explainer, glossary, agency links
13. **Reports and Analytics** – HTML report, CSV, print or save as PDF
14. **Settings and About** – theme, defaults, clear local data, backend check

## Real Earth images
The globe loads NASA-based textures from the three.js examples (internet needed). To work offline, download `earth_atmos_2048.jpg`, `earth_lights_2048.png` and `earth_clouds_1024.png` from https://github.com/mrdoob/three.js/tree/r147/examples/textures/planets and put them in `frontend/assets/`. The top-bar chip shows whether they loaded.

## Run the website
```bash
cd frontend
python -m http.server 5500
```
Open http://localhost:5500. Internet is needed for the Three.js, Chart.js and Earth texture links. (In VS Code you can use the Live Server extension instead.)

## Run the backend (optional)
```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload
```
API docs: http://127.0.0.1:8000/docs. Tests: `pytest` (inside `backend`).
Endpoints: `GET /api/health`, `POST /api/screen`, `POST /api/validate`.

## Importing data
- **CSV columns:** `id,type,alt_km,inc_deg,raan_deg,ma_deg` (optional `name`). Types: satellite, debris, rocket_body. See `sample-data/sample.csv`.
- **TLE:** 2-line or 3-line files (for example from celestrak.org). Checksums are validated.
- Not supported: OMM and other formats (shown as an error).

## Scientific limits
- Orbits are circular two-body models in an inertial frame. No SGP4, perturbations, eccentricity or covariance.
- TLE epoch is ignored, so imported TLE objects are not real positions.
- Fragment, drag, detection and prediction models are teaching simplifications.
- Catalogue density is not the same as collision probability or the true debris population.

## Not included
Live CelesTrak download, SGP4 propagation, ML trained on real data (scikit-learn), native PDF export, user accounts.
